## 私有样本的新证据

样本内 12 项资源逐一核对大小和 SHA-256。报告所列原包哈希与既有目标一致；两套全局流的 buttons 和 minion_pro 资源分别逐字节相同。buttons FONT v7 的 38 个原字形编号连续为 0–37。

buttons 纹理是 512×256 DXT5/BC3；按 16 位交换字节后可正确解码图标。在保持所有原图标矩形与整张纹理可见像素不动的保守扫描中，可排出 8 个 28px 空白格、62 个 16px 格，或 132 个 12px 格。这些是贪心排布的几何样本，不是可安装容量承诺；还要满足原 RefPack 压缩槽位和字体元数据空间。12px 格意味着更小的实际字形，不能把几何数量直接当成清晰文字容量。

已离线试制 38、39 两个追加字形，保留原 38 条记录及图标像素，原纹理头不变。该实验尚未形成已通过的安装包；原始样本和解码预览不上传公开仓库。

## 第二字库成功后的使用顺序

1. 先区分 G0 已有编号显示成功与新增编号 38/39 显示成功；仅能显示旧图标还不足以证明可追加汉字。
2. 确认新增字形的大小、基线、中文混排、换行与按键图标均正常。
3. 按菜单和操作说明的共用字频分配两套字库，普通字库存放高频字，第二字库承接溢出字，不重复浪费字形位置。
4. 每批按实际压缩长度选择可装入的范围，保留正常操作图标，再处理关卡字体流与切换。
5. 继续逐条保留原按钮/颜色/占位符及换行；任何中文图标编码均作为明确的构建映射，不能放宽普通译稿的控制符校验。

稳定基线仍为用户已确认的 F1。第二字库与 F2 的新增范围均等待各自实机反馈。
