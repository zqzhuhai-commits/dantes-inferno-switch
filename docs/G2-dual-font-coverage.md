# G2 v0.8.0：扩大双字库非字幕覆盖

## 用户已确认的基线

F1 可进入游戏，菜单已有汉化。G0 可进入游戏，数字标记变为按键图标；用户截图显示原“开始”位置为 BACK、原“选项”位置为 START，其余中文菜单仍可见。这确认既有第二字体通道在菜单中可用。用户要求不再发布两字探针，直接扩大实际译文覆盖。本轮按此要求制作 G2，不把 G0 的结果记成 G2 实机通过。

## 实际产出

- 普通字库 771 字形，仍为 512×256 A8、12px 位图、两倍几何度量、4 级透明度。压缩 FONT 9,728 字节，纹理 31,612 字节。
- 第二字库保留 38 个原按键图标，最多追加 62 个数字字形。只写原图标和整张纹理可见像素之外的透明空白格，原图标记录与像素保持不变。仍为原 512×256 DXT5/BC3，纹理头不变。
- 直接写入可被这两套字形完整覆盖的非字幕译文，不缺字地截断句子，也不删除原按钮标记。先校验原始人类译稿的控制符，再把溢出字编译为数字图标标记，反向解码须与译稿逐字相等。
- 两份全局英文文本表 752、1437 都修改，字幕表 942 不动。未纳入的全局条目保留原文。
- 字体流 2095、298 都纳入更新；五份 TOC 同时更新正确关联的字体流解码长度和实际文本表长度。

## 在原总容量内选择最大候选

优先使用原压缩块槽位。如果关卡等字体槽位装不下，则在同一 STR 条目的总容量内重排压缩块，尾部 FILL 补齐；不追加 VIV 资源，不改 VIV 索引、条目位置/长度或整个 VIV 的大小。重排会改变 STR 内部部分区块偏移，不能把它描述成“全部 STR 区块位置不变”。所有非字体资源的区块字节和相对顺序须相同，替换字体重新解压须逐字节相等。

安装器从 62 字方案开始检查两份字体流，容量不足时尝试较小候选。实际候选、覆盖数、字幕表不变及 STR 放置方式写入 `G2-build-report.json`。该报告的 stage 为 resource_preflight_only，表示资源准备成功，不代表完整文件生成或实机通过；完整生成还必须通过安装器后续整包和资源校验。

## 验证及尚未验证的范围

68 项工具测试通过，包括 F1 字形像素/度量保持、UV 边界/不重叠、所有候选字形覆盖、翻译与编译映射双向校验、按钮/颜色/占位符/换行保持、两套 TOC 根大小关联、原容量内重排和压缩资源重读、ZIP 资产清单。没有完整原 VIV，因此本轮没有真实 VIV 端到端生成或实机运行结果。原包校验和输出预期哈希模型在安装时执行，不能替代兼容性验证。

尤其需要实际观察新增数字字形、普通文字/图标字体混排的尺度与基线、自动换行、关卡切换及 STR 内部重排。用户已要求直接扩大，本包不以额外探针测试为前置门槛，但不把这些行为记为已证实。

## 安装与恢复

退出游戏，恢复同一原版 bigfile0.viv，不能叠加已有补丁。电脑需 Python 3.9+（含 Tk），解压后运行 RUN_G2.bat，预留约 3.3 GB。所有检查通过后才备份安装。语言保持 English。

检查主菜单、选项、操作教程、关卡暂停/技能/圣物菜单，以及返回主菜单。若生成或加载失败，请保留错误信息/生成报告并恢复原版。退出游戏后，把工具保存的 `.original.日期.bak` 恢复为 bigfile0.viv，或恢复此前保留的 F1。NRO/NSP/bigfile1 不改。

原始字体样本和用户截图不上传公开仓库；仓库仅保存修改资产、源码、译稿清单及验证记录。


## 关闭字幕与容量

用户默认关闭字幕。G2 本来就不修改字幕表942，关闭游戏字幕选项不会增大补丁的固定纹理或资源槽位。当前最大候选的1066条不是全量1664条。后续若要全部容纳，仍要继续调整字形排布、分配和压缩，不能将关闭字幕本身视为完成扩容。
